# 分阶段工程路线

每个阶段必须形成可测试的闭环，不能同时铺开全部功能。

## Phase 0：冻结最小协议

定义：

- UserId / DeviceId / NodeId
- ConversationId / EventId
- EventEnvelope
- NodeDescriptor
- DeliveryReceipt
- 版本协商

验收：

```text
编码 → 解码 → 签名 → 验签 → 存储 → 重放
```

结果完全一致，并有固定测试向量。

## Phase 1：本地聊天内核

实现：

- 创建身份
- 创建会话
- 文本消息
- 编辑、撤回、回复
- SQLite 持久化
- 时间线投影
- 崩溃恢复

验收：删除投影表后能从事件日志重建完整界面。

## Phase 2：在线单对单

暂时使用明确地址或二维码交换连接信息。

实现：

- 安全连接
- 版本协商
- 发送和 ACK
- 超时、重试
- 乱序和去重
- 断线重连

验收：重复、乱序、掉线不会产生重复消息或错误状态。

## Phase 3：Relay

实现：

- 节点角色声明
- 直连失败自动回退
- 流量限制
- 最大连接数
- 基础滥用防护

验收：两个不同 NAT 后的客户端稳定通信，Relay 不能读取正文。

## Phase 4：离线 Mailbox

实现：

- 带 TTL 的密文投递
- 持久化回执
- 拉取游标
- 删除确认
- 多 Mailbox 去重
- 配额和迁移

投递语义：网络和 Mailbox 只承诺至少一次投递，允许超时重试、重复拉取和 ACK 丢失；客户端以 `EventId` 幂等去重，并在同一数据库事务中写入事件与消费检查点，因此只产生一次本地事实。不得把它描述为网络“恰好一次”。

验收：接收者离线和两端多次重启后仍能完整收到消息；故障注入可产生重复投递，但同一 `EventId` 最终只在本地 Event Store 提交一次。

## Phase 4.5：MVP 图片和小文件

在文本消息、Relay 和 Mailbox 的纵向闭环稳定后接入附件，不提前铺开完整媒体平台。

实现：

- 通过受控文件选择器导入图片和小文件
- 流式加密、分块、断点续传和完整性校验
- 聊天事件只携带加密 manifest 引用，不内嵌文件或本地路径
- Blob 节点只保存 opaque ciphertext chunks
- 下载完成并验证后才允许解密导出

验收：完成“选择文件 → 加密上传 → 发送引用 → 跨网络下载 → 校验 → 导出”的端到端切片；重复、乱序、断线和任一 chunk 篡改不会产生重复附件事实或成功的损坏明文输出。

## Phase 5：多设备身份

实现：

- 根身份
- 设备授权
- 设备撤销
- 新设备同步
- 二维码验证
- 恢复机制

验收：撤销设备后，该设备不能读取后续消息。

## Phase 6：移动端与推送

顺序：Android → iOS。

Push 只携带随机唤醒标识和 Mailbox 提示，不携带聊天元数据。

验收：应用被系统挂起后能收到无内容通知，打开后完成密文同步。

## Phase 7：小型群组

首版限制几十个成员。

实现：

- 加入、退出、移除
- 管理员和角色
- 成员状态 Epoch
- 群组密钥 Epoch
- 并发控制事件

基础投递稳定后再接入 MLS。

## Phase 8：节点网络

实现：

- Bootstrap
- DHT
- Peer Exchange
- AutoNAT
- 打洞
- 自动 Relay
- 多 Mailbox
- 节点能力声明
- 健康检查

验收：关闭默认节点后，用户可通过自选节点继续正常通信。

## Phase 9：频道

实现：

- 公共发布者签名
- Gossip 扩散
- 内容寻址
- 缓存和历史归档
- 私有频道加密

## Phase 10：自动化

先本地、后会话、再远程：

- AgentId
- Capability
- Trigger
- Proposal
- Approval
- ExecutionResult
- WASM 沙箱

高风险操作必须使用提议—批准流程。
