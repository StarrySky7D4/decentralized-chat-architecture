# 设计原则

## 1. 去中心化的目标

本项目不追求“所有设备永远直接互连”，而追求以下性质：

- 用户身份不依赖单个账户服务器。
- 会话内容默认端到端加密。
- 本地数据库是客户端状态源。
- 网络投递路径可以替换。
- 公共服务节点只提供能力，不拥有用户。
- 节点运营权可以逐渐从开发者扩散到社区和用户。

## 2. 服务器是一种节点角色

服务器并不是一种特殊的软件实体。任何具备稳定在线、公网可达、存储和带宽的节点，都可以承担：

- Bootstrap
- Relay
- Mailbox
- Directory
- Blob
- Push Bridge
- Federation
- SFU

因此需要消除的是“唯一且不可替换的中心”，而不是所有稳定节点。

## 3. 本地优先

发送消息时先完成本地提交：

```text
创建事件
  → 本地签名/加密
  → SQLite 持久化
  → UI 立即显示 pending
  → 后台多路径投递
  → 收到回执后更新状态
```

网络失败不应阻塞本地操作，重启后投递任务应继续执行。

## 4. 不可变事件

消息创建、编辑、撤回、成员变化和权限变化都表达为新事件，不直接覆盖历史事实。

优点：

- 多设备同步简单。
- 可以去重和重放。
- 网络乱序时仍可合并。
- 投影损坏后可以重建。
- 自动化行为可以审计。

## 5. 异构节点

现实中的手机、桌面、NAS 和 VPS 能力不同，因此节点不应强制完全同质：

- 手机是轻节点。
- 桌面和 NAS 可以是完整节点。
- VPS 和社区机器可以是服务节点。
- 少量种子节点帮助新节点进入网络。

## 6. 渐进式去中心化

首版可以由开发者运行默认 Bootstrap、Relay 和 Mailbox，但必须从一开始满足：

- 协议公开。
- 服务可替换。
- 用户可配置节点。
- 节点不能解密正文。
- 身份不绑定运营者。

这比“首版强行零服务器但无法可靠通信”更可持续。
