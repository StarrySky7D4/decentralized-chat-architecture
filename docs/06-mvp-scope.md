# 首个可发布版本范围

## 支持

- Windows 与 Linux 桌面客户端
- 一对一文本消息
- 图片和小文件
- 本地完整历史
- 邀请码或二维码添加联系人
- 端到端加密
- 一个默认 Bootstrap
- 一个默认 Relay
- 一个默认 Mailbox
- 自定义节点地址
- 消息重试、去重和离线送达

## 暂不支持

- 大型群组
- 公共频道
- 音视频
- Web 客户端
- 跨域联邦
- 插件市场
- 全球匿名发现
- 全球唯一用户名
- 复杂社交恢复
- 自动化市场

## 架构要求

即使 MVP 使用开发者提供的默认节点，也必须保证：

```text
节点可替换
节点可自托管
节点不能解密正文
身份不绑定节点
协议公开
客户端保留完整本地历史
```

## MVP 成功标准

1. 两台不同网络下的桌面设备可稳定通信。
2. 接收端离线时消息可以持久保存。
3. 中继和邮箱节点无法读取内容。
4. 客户端重启后不会丢失或重复消息。
5. 默认节点停止后，修改配置即可迁移到另一组节点。
6. 核心协议拥有测试向量和版本协商。
7. 所有网络故障都表现为可恢复状态，而不是数据库损坏。
