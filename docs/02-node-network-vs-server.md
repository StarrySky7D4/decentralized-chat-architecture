# 节点网络如何替代服务器

## 可以替代什么

| 传统职责 | 节点网络方案 | 结果 |
|---|---|---|
| 在线转发 | 直连、打洞、Relay | 大部分替代 |
| 离线消息 | 多个 Mailbox 保存密文 | 可替代 |
| 用户发现 | 邀请、二维码、DHT、目录节点 | 可替代 |
| 群组广播 | 成员复制、Gossip、缓存节点 | 可替代 |
| 附件存储 | 加密分块、多节点复制 | 可替代 |
| 历史记录 | 用户设备、自选备份节点 | 可替代 |
| 搜索 | 本地索引 | 可替代 |
| 自动化 | 本地 Agent、自选执行节点 | 可替代 |
| 多人媒体 | 可替换社区 SFU | 可分散 |

## 难以完全替代什么

### 移动设备唤醒

iOS 和 Android 的可靠后台唤醒通常仍需要平台推送系统。解决方案不是把明文交给平台，而是让 Push Bridge 只发送无内容提示：

```text
random_wakeup_id
mailbox_hint
```

客户端被唤醒后，主动从 Mailbox 获取端到端加密信封。

### 稳定在线和公网可达

多数用户设备位于 NAT、防火墙或移动网络后，并且经常离线。节点网络仍需要少量公网稳定节点承担：

- 引导
- 中继
- 短期邮箱
- 公共内容缓存

这些节点在功能上就是服务器，但不应成为协议中心。

### 反滥用和资源供给

开放网络需要解决：

- 垃圾消息
- 大量连接
- 存储滥用
- 中继带宽盗用
- DHT 污染
- Sybil 节点

这需要邀请机制、配额、工作量或其他成本证明、信誉隔离和节点本地策略。它们可以分散实现，但不能被架构忽略。

## 正确目标

错误目标：

> 没有任何服务器机器。

正确目标：

> 没有任何不可替换、可解密、可冻结全部用户的唯一服务提供者。

## 渐进替代过程

```text
阶段 A：开发者节点承担 Bootstrap + Relay + Mailbox
阶段 B：允许用户配置自己的节点
阶段 C：桌面客户端可选择提供 Relay/Mailbox
阶段 D：社区发布稳定服务节点
阶段 E：多节点发现、自动选择和迁移
阶段 F：开发者节点降级为默认选项之一
```
