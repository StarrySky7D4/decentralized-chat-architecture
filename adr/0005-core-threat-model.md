# ADR-0005：采用核心端到端加密威胁模型

- 状态：Accepted
- 日期：2026-08-04

## 背景

仓库已经描述了本地优先事件模型、设备身份、Direct/Relay/Mailbox 投递和未来匿名网络，但此前没有一份覆盖普通端到端加密聊天的统一威胁模型。匿名覆盖层文档关注路径匿名与流量分析，不能回答恶意联系人、失陷设备、服务串谋、Push/Blob、恢复和资源耗尽对基础产品的影响。

缺少统一边界会使“节点不能解密正文”被误读为完整安全保证，也无法为协议冻结、实现合入和 MVP 发布提供一致的阻断门槛。

## 决策

采用 `docs/08-core-threat-model.md` 作为 `StandardE2ee` 核心层的规范性安全基线，并作出以下决定：

1. 客户端端点是明文信任边界；联系人和所有网络/服务输入均不可信。
2. Relay、Mailbox、Directory/Bootstrap、Push、Blob 均按可能恶意且可能串谋建模，不作为身份、消息事实或恢复信任根。
3. 核心层承诺内容机密性、来源与完整性验证、明确的撤销/重放/回执语义和有界资源使用；不把 E2EE 宣传为匿名。
4. 普通路径仍会泄漏 IP、时序、尺寸、在线状态或关系元数据。需要抵抗这些风险时使用另行评审的匿名覆盖层，且不得自动降级。
5. 失陷设备在撤销前可读取和伪造其权限内的数据；系统通过安全存储、最小暴露、撤销和密钥轮换限制未来影响，但不承诺在完全端点控制下保持机密。
6. 恢复不得复活已撤销设备、降低身份验证或让单个服务持有恢复能力。具体恢复设计未完成前不得声称账户可恢复。
7. 文档中的安全不变量和分阶段验证清单是发布阻断条件；新增服务、字段、遥测、SDK 或权限必须重新进行威胁建模。

## 后果

优点：

- 产品安全声明与匿名能力边界清晰，不再把“服务看不到正文”等同于隐藏关系元数据。
- 模块可以围绕同一组 A0–A9 对手、安全不变量和负向测试建立 conformance suite。
- 回执、撤销、备份恢复、Push 和附件具有统一 fail-closed 要求。
- 发布者必须披露仍可见元数据、已知限制与审计状态。

代价：

- 协议冻结和 MVP 发布增加数据流评审、测试向量、模糊测试、恢复演练、供应链检查和独立安全评审成本。
- 默认服务不能依靠读取正文来完成滥用治理，需要配额、用户主动举报和本地控制等替代机制。
- 完成威胁模型不代表密码实现、元数据审计或密钥恢复已完成；这些任务仍需独立验收。

## 被否决的方案

- **只引用匿名覆盖层威胁模型**：其目标和对手重点不同，且明确不解决端点失陷。
- **仅把服务节点设为诚实但好奇**：无法覆盖丢弃、重放、伪造回执、Sybil、资源耗尽及服务串谋。
- **把 TLS 当作端到端保护**：TLS 只保护单段链路，Relay/Mailbox 仍位于应用消息路径中。
- **在实现完成后再做威胁建模**：会使 wire 格式、日志、恢复和回执语义形成难以兼容修正的安全债务。

## 复审触发条件

以下任一变化必须复审本 ADR 和核心威胁模型：引入群组/MLS、Web 客户端、联邦、匿名路径、社交恢复、自动化 Agent、服务端内容处理、新 Push/遥测 SDK、密钥算法迁移，或发生改变信任边界的安全事件。
