# ADR-0006：设备会话事件序列

- 状态：Accepted
- 日期：2026-08-04

## 背景

`EventEnvelopeV0` 包含 `actor_sequence`，但若不定义作用域、分配和异常语义，不同实现会把它误作用户全局序号、连续 offset 或仅一次投递凭据。多设备离线写入无法安全共享用户级计数器；全局设备计数器还会造成跨会话关联。崩溃、备份回滚和设备克隆也可能导致序号复用。

## 决策

### 作用域与含义

`actor_sequence` 是 `(ConversationId, DeviceId)` 通道内从 1 开始、严格单调、永不复用的序号。它为同一设备在同一会话中的事件提供稳定顺序与 equivocation 检测，不表达跨设备顺序、全局时间、控制/密码 Epoch 或投递次数。

设备作用域允许同一用户的多个设备离线并发；会话作用域避免一个跨会话递增值成为关联标识。跨设备因果关系只由 `parents` 表达。

### 分配与崩溃

事件创建 owner 使用持久 CAS/事务分配器原子保留序号，并在同一事务绑定 `OperationId`。保留必须先于签名或网络可见性 durable commit：

- 事务提交前崩溃：没有分配；
- 保留提交后、事件完成前崩溃：留下合法缺号；
- 事件提交后崩溃：按 `OperationId`/`EventId` 恢复同一结果。

已保留序号不回收、不转给另一 operation。序号不得参与 nonce 或 key 派生。实现可以批量保留，但批量中未使用的值永久成为缺号。

### 接收、重放与冲突

缺号不阻塞，较小序号晚到不因本地 high-water mark 被拒绝。相同 `EventId` 是幂等重放；网络语义是至少一次投递，Event Store 用 `EventId` 唯一性实现一次本地事实提交。

同一通道、同一 sequence 出现两个不同且签名有效的 EventId 是 `SequenceEquivocation`。两者及依赖后继隔离并保留证据，不使用到达时间、logical time 或 EventId 选赢家。投影按父边和已知同通道序列边拓扑排序；ready set 使用稳定 total key，晚到较小序号触发受影响会话重放。

### 撤销与恢复

设备撤销不改变撤销前按相应快照有效的历史事件；撤销生效后的新事件不准入。计数器不重置。备份恢复必须证明 high-water mark 不回退；否则旧设备身份停止写入，并授权新 `DeviceId`。

## 被否决方案

- **用户级全局序列：** 多设备离线时需要不可用的共识分配器。
- **设备级全局序列：** 技术上可行，但泄露跨会话相关性，且无必要。
- **要求连续无缺号：** 崩溃或预留会永久阻塞同步，并诱使实现复用序号。
- **冲突时选择较小 EventId/LWW：** 会隐藏设备克隆或签名者 equivocation，且把安全事件伪装成普通并发。

## 后果

优点：离线多设备无需共享计数器；去重、稳定排序和设备克隆检测的语义明确；崩溃不会迫使复用。

代价：每个设备会话通道需要持久 high-water mark；缺号不能证明丢消息；晚到事件可能要求局部重放；无法恢复 high-water mark 时必须轮换设备身份。

## 验证

- 并发/属性测试证明每通道分配唯一且单调。
- 在事务前、reservation 后、事件提交后注入崩溃，验证仅产生缺号而不复用。
- 随机缺号、乱序、重复到达和晚到较小值后，增量投影与全量重建哈希一致。
- 同 sequence 不同签名事件稳定产生 `SequenceEquivocation`；相同 EventId 重放为 no-op。
- 撤销与旧备份恢复不能让旧 `DeviceId` 重新从较小 high-water mark 写入。
